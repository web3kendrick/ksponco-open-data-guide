# 한국체육산업개발 공공데이터 이용 안내

한국체육산업개발이 공공데이터포털에 개방한 파일데이터 30종을 내려받아, 파일 안의 실제 자료 기간과 이용 시 주의점을 계산하고 포털 설명과 나란히 보여 주는 정적 웹 페이지입니다. 이 기관의 데이터를 내려받아 서비스나 분석을 만들려는 개발자, 학생, 연구자가 주 이용자이고, 셋째 화면은 포털 설명을 관리하는 담당 부서를 위한 설명 갱신 제안입니다.

비공식 참고 자료이며 한국체육산업개발의 공식 안내와는 별개입니다.

## 대표 숫자 (자료 기준일 2026-11-23)

- 설명에 기간이 적힌 11건 중 6건은 실제 자료가 설명보다 10개월에서 24개월 더 최신
- 다른 데이터의 설명이 붙은 파일 1건, 설명에 기간이 없는 파일 18건
- CSV 29개 중 29개의 행 수가 포털 '전체 행'과 같음
- 이용 시 주의점 13종에 21건

이 숫자는 `build/build.py`가 원자료에서 계산해 `docs/data.json`에 쓴 값이며, 화면은 이 파일만 읽습니다. 화면에 손으로 적은 숫자는 없습니다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `docs/` | 정적 사이트. HTML, CSS, 자바스크립트만 쓰고 외부 요청, 빌드 단계, 프레임워크가 없음 |
| `docs/data.json`, `docs/data.js` | 계산 결과. 두 파일의 내용은 같고, `data.js`는 파일을 직접 열어도 화면이 뜨도록 둔 사본 |
| `build/build.py` | 원자료를 읽어 모든 숫자를 다시 계산하는 스크립트 (파이썬 표준 라이브러리만 사용) |
| `build/fetch_pages.py` | 공공데이터포털의 데이터 쪽 30개를 날짜 폴더에 저장 (HTML만, 데이터 파일은 받지 않음) |
| `build/datasets.json` | 데이터 번호, 분야, 파일별 주 날짜 칸, 다음 대조 예정일(`next_check`), 누리집 인용 문장과 확인일 |
| `build/period_rules.json` | 포털 설명 속 기간 표현을 손으로 확인해 고정한 규칙표 |
| `build/test_site.js` | 브라우저 없이 모든 화면을 그려 보는 점검 (Node.js) |
| `raw/` | 내려받은 원자료. 저장소에는 올리지 않음 |

## data.json 다시 만드는 방법

1. 아래 표의 공공데이터포털 쪽에서 파일을 내려받아 `raw/files/<데이터 번호>/data.bin`으로 저장합니다. 로그인은 필요 없습니다.
2. `raw/files/manifest.json`에 데이터 번호별로 내려받은 날(`downloaded_kst`), 원래 파일 이름(`filename`), 크기(`bytes`)를 적습니다.
3. 포털의 데이터 쪽을 그날 날짜로 저장합니다.

   ```
   python build/fetch_pages.py 2026-11-23
   ```

4. `build/datasets.json`의 `next_check`를 다음 대조 예정일로 고칩니다. 화면 점검은 이 날짜가 자료 기준일보다 늦은지 확인합니다.

5. 계산을 돌립니다. `raw/pages` 아래 가장 늦은 날짜 폴더가 자료 기준일이 되고, 그 앞 날짜 폴더가 있으면 바뀐 점을 함께 계산합니다. 대표 숫자 표가 화면에 찍히고 `docs/data.json`과 `docs/data.js`가 새로 쓰입니다.

   ```
   python build/build.py
   ```

6. 화면 점검을 돌립니다.

   ```
   node build/test_site.js
   ```

7. 로컬에서 엽니다. `docs/index.html`을 직접 열어도 되고, 아래처럼 띄워도 됩니다.

   ```
   python -m http.server 8000 --directory docs
   ```

배포는 `docs/` 폴더를 정적 호스팅에 그대로 올리면 됩니다. 모든 주소가 상대 경로라서 하위 경로에서도 동작합니다.

## 계산 규칙

1. 포털 설명에서 자기 자료의 기간을 적은 표현을 손으로 확인해 `build/period_rules.json`에 고정합니다. 표현이 포털 설명에서 사라지면 그 데이터는 '설명이 바뀜'으로 표시됩니다.
2. 설명상 기간은 적힌 연월입니다. 연도만 있으면 시작은 그해 1월, 끝은 그해 12월로 봅니다.
3. 실제 자료 기간은 파일의 주 날짜 칸에서 가장 이른 달과 가장 늦은 달입니다. 2000년 이전과 2027년 뒤의 날짜는 기본값이나 오타로 보고 뺍니다. 정보목록데이터처럼 제목에 'YYYY년 M월'로 자료의 달이 적힌 파일은 등록일 대신 제목의 연월을 씁니다(`build/datasets.json`의 `title_col`).
4. 실제 끝 시점이 설명상 끝 시점보다 늦으면 '설명보다 최신'으로 셉니다.
5. 이용 시 주의점(기본값 날짜 1990-01-01과 9999-12-31, 범위 밖 날짜, 중복 행, 같은 내용이 되풀이되는 달, 지난 등록 예정일, 포털 행 수와의 차이)은 모두 파일에서 센 값입니다.
6. 값 종류가 많은 글자 칸의 값과 표본 행은 싣지 않습니다. 강좌명 같은 칸에 사람 이름이 들어 있을 수 있기 때문입니다.
